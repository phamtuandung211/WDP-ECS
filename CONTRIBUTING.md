# Contributing to WDP-ECS

## Code Style

- Use ES6+ syntax
- 2-space indentation
- Semicolons required
- No trailing commas

## Git Workflow

1. Create feature branch: `git checkout -b feature/feature-name`
2. Make changes and commit: `git commit -m "feat: description"`
3. Push: `git push origin feature/feature-name`
4. Create Pull Request

## Commit Messages

Follow conventional commits:

- `feat:` new feature
- `fix:` bug fix
- `docs:` documentation
- `style:` code style
- `refactor:` code refactoring
- `test:` tests
- `chore:` build, deps

Example: `feat: add appointment booking endpoint`

## Testing

- Test API endpoints before merging
- Test UI components before committing
- Use `.env.example` for testing

## Pull Request Process

1. Update documentation
2. Test thoroughly
3. Request review from team
4. Address feedback
5. Merge after approval

## Issues & Bugs

- Create GitHub issue with clear title
- Describe expected vs actual behavior
- Include error messages/logs
- Tag appropriately

## Questions?

Reach out to team lead or create a discussion.
